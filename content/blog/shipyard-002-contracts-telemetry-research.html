A distributed system gets dangerous when its components share assumptions instead of contracts.

Recent StarIntel work is mostly about deleting those assumptions.

Source Actors and Targets now have an explicit protocol

The StarIntel server's current head adds documentation defining the Source Actor and Target protocols.

Source: starintel-server f899612d

That sounds less exciting than another scraper.

It is more important.

Actors need a stable answer to questions such as:

  • What exactly am I receiving?
  • What identity does this target carry?
  • What may I emit?
  • Which pieces are source data versus derived data?
  • Which protocol owns dispatch?
  • Where does provenance survive the transition?

Writing these contracts down is part of making actors replaceable. A YouTube collector, domain actor, court-record actor, or future StarLang runtime should not need private knowledge of whoever wrote the router.

Hosted observability became explicit

The server also landed a run of observability work around hosted telemetry:

  • explicit telemetry configuration
  • audited search-query behavior
  • explicit gate and sidecar endpoint wiring
  • idempotent transport installation

Source: starintel-server e49c67d8

The key word is explicit.

Telemetry that mysteriously appears because some package happens to be loaded is hard to reason about and harder to trust.

StarIntel is moving toward infrastructure where enabling the observation path is itself visible configuration.

Auto Research reached the website

The main website now has a first-class /research surface backed by a bounded server-side research-health projection.

The implementation also tests fail-closed behavior when that integration is not configured.

Source: website 3956fd04

This keeps the public boundary intentionally narrow.

The website does not become a window directly into private research storage. It gets a projection designed for publication.

That distinction is the same one used elsewhere in StarIntel:

internal state
     ↓
policy / projection
     ↓
bounded public representation

Business automation is getting symbolic policy too

On the business side, starintel-biz merged an autonomous opportunity board and OSINT target pack.

The slice includes a Prolog policy layer, tests, structured targets, research notes, and a prototype lead board.

Source: starintel-biz da88ad47

That is a pattern worth keeping: business automation should still be inspectable as rules and structured data instead of disappearing inside one giant prompt.

What is still design, not runtime

The infrastructure repository also gained the hosted Zara paid multi-tenant platform design.

That commit is documentation.

It is not evidence that the hosted platform is production-ready, and Shipyard is going to keep saying that kind of thing out loud.

Source: starintel-infra e2f047af

Design landing in Git is still progress: it gives implementation something concrete to satisfy.

It just is not the same progress as a running service.

The direction

Taken together, these changes point at a fairly consistent architecture:

contracts
   ↓
actors
   ↓
typed state
   ↓
symbolic policy
   ↓
bounded projections
   ↓
operator / public interfaces

StarIntel does not need every component to be intelligent.

It needs every component to be legible.

That is the stuff leaving the Shipyard this week.
